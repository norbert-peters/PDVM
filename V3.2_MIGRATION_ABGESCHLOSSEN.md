## 🎯 Problem (V3.1)

**Fehler beim Zurückkehren zum Startmenü**:
```
RuntimeError: wrapped C/C++ object of type QTextEdit has been deleted
```

**Ursache**:
1. Pipeline löscht Workspace in STEP 3.1 (inkl. `welcome_widget`)
2. Handler ruft `_show_welcome_message()` auf
3. → Verwendet gelöschtes Widget → **CRASH**

**User-Feedback**:
> "irgendwo machst du es zu kompliziert und deine Reihenfolge stimmt nicht"

---

## ✅ Lösung (V3.2)

### Kern-Prinzip: **Handler fügen KEINE Widgets direkt ein**

**Neue Ablauf-Logik**:
```
1. Handler bereitet Daten vor (lädt Menü, setzt _current_app_name)
2. Pipeline prüft Workspace nach Handler-Ausführung
3. Pipeline fügt Welcome-Screen ein (NEUES Widget!)
```

### Pipeline-Signatur (erweitert)

```python
def workspace_pipeline(
    self, 
    command_func=None,           # Handler-Funktion
    error_message=None,          # Fehlermeldung (optional)
    skip_clear=False,            # False = Workspace leeren
    alternativ_skip_clear=False, # True = Nach skip_clear Workspace löschen
    alternativ_func=None         # Custom-Funktion für Workspace-Füllung
) -> bool:
```

### Lineare Schritte

**skip_clear=False** (Standard: View/Menü öffnen):
```
STEP 3.1: Workspace LEEREN (inkl. altes welcome_widget)
STEP 3.2: Handler ausführen (lädt Menü, KEIN Widget einfügen!)
STEP 3.3: Workspace leer? → NEUES welcome_widget einfügen
```

**skip_clear=True** (UI-Toggles):
```
STEP 4.1: Workspace BEHALTEN
STEP 4.2: Handler ausführen (Toggle-Aktion)
STEP 4.3: alternativ_skip_clear=False → Pipeline Ende
          alternativ_skip_clear=True → Workspace löschen + alternativ_func
```

## 📋 Geänderte Dateien

### 1. `v2_systemstart.py` (Hauptänderungen)

**Neue Methoden**:
```python
def _clear_workspace_layout(self):
    """Löscht ALLE Widgets aus workspace_layout"""
    while self.workspace_layout.count() > 0:
        item = self.workspace_layout.takeAt(0)
        widget = item.widget() if item else None
        if widget:
            widget.hide()
            widget.deleteLater()

def _insert_welcome_screen(self):
    """
    Fügt Welcome-Screen in workspace_layout ein
    WICHTIG: Erstellt NEUES Widget (altes wurde gelöscht!)
    """
    # Erstelle NEUES Widget
    self.welcome_widget = self._create_welcome_widget()
    self._show_welcome_message()
    
    # Füge in Workspace ein
    self.workspace_layout.addWidget(self.welcome_widget)
    self.welcome_widget.show()
    
    # App-Name einfügen (falls gesetzt)
    if hasattr(self, '_current_app_name') and self._current_app_name:
        # ... HTML-Anpassung ...
        self._current_app_name = None  # Reset
```

**Überarbeitete Methode**:
```python
def workspace_pipeline(self, command_func=None, error_message=None, 
                      skip_clear=False, alternativ_skip_clear=False, 
                      alternativ_func=None):
    """V3.2: LINEARE PIPELINE nach User-Vorgabe"""
    
    # STEP 3.1 / 4.1: Workspace leeren (bedingt)
    if not skip_clear:
        self._clear_workspace_layout()
    
    # STEP 3.2 / 4.2: Hauptaufruf ausführen
    if command_func:
        result = command_func()
    
    # STEP 4.3-4.5: Alternativ-Logik (nur bei skip_clear=True)
    if skip_clear:
        if alternativ_skip_clear:
            self._clear_workspace_layout()
            if alternativ_func:
                alternativ_func()
            elif self.workspace_layout.count() == 0:
                self._insert_welcome_screen()
        return result
    
    # STEP 3.3: Workspace-Füllung garantieren
    if self.workspace_layout.count() == 0:
        if alternativ_func:
            alternativ_func()
        else:
            self._insert_welcome_screen()
    
    return result
```

**Handler-Updates**:
```python
def handler_return_to_startmenu(self):
    """V3.2: KEIN _show_welcome_message() mehr!"""
    def _load_startmenu():

            success = self.menu_handler.load_startmenu()
```

## 🚀 User-Feedback Umgesetzt

**User-Anforderung**:
> "Es muss vom Ablauf her bei allen gleich laufen:
> 1. Handler wird aufgerufen
> 2. Handler bereitet seine Parameter für die Pipeline auf
> 3. Die Pipeline arbeitet folgendermaßen..."

**Umsetzung**: ✅ **100% wie gefordert**
- ✅ Handler bereiten Daten vor (Menü laden, _current_app_name setzen)
- ✅ Pipeline arbeitet linear (3.1 → 3.2 → 3.3)
- ✅ Alle Handler folgen gleichem Pattern (skip_clear=False)

**User-Vorschlag**:
> "Eine Überlegung ab 4.3 könnte man auch die Pipeline über einen Handler im Handler nochmals aufrufen"

**Implementiert**: ✅ **Möglich mit alternativ_func**
- Handler kann eigene Funktion als `alternativ_func` übergeben
- Ermöglicht rekursive Pipeline-Aufrufe für komplexe Szenarien
